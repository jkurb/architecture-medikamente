# Диаграммы потоков данных To-Be (с мерами защиты)

Доработанные диаграммы: на каждом этапе потока указаны применяемые меры. Сквозные меры для всех процессов:

- аутентификация через IdP (Keycloak + AD), MFA;
- доступ по тегам данных (RBAC/ABAC), least privilege;
- TLS для всех соединений, шифрование хранилищ at rest;
- аудит всех обращений к данным `c2/c3` → SIEM (Elastic) → алертинг при нетипичных действиях;
- DLP на периметре (почта, USB, печать).

## P1. Запись пациента на приём

```mermaid
flowchart LR
    PAT[Пациент]
    REC(P1. Регистрация записи<br/>портал ресепшена<br/>RBAC: роль reception)
    DB[(БД записей и договоров<br/>Postgres, теги c2,<br/>шифрование at rest)]
    DOC[Мед. специалист]
    AUD[(Журнал аудита<br/>SIEM)]

    PAT -- "Ф. И. О., телефон, e-mail<br/>TLS, минимальный состав полей" --> REC
    REC -- "запись + договор<br/>паспорт: маскирование в UI" --> DB
    DB -- "расписание без ПДн сверх<br/>необходимого: Ф. И. О., время" --> DOC
    DB -- "напоминание: только имя,<br/>дата, время" --> PAT
    REC -. "все операции" .-> AUD
```

Меры: Data Minimization на форме ввода; паспортные данные видны только роли, оформляющей договор; журнал в Excel упразднён.

## P2. Приём пациента и ведение медицинской карты

```mermaid
flowchart LR
    PAT[Пациент]
    VISIT(P2. Ведение ЭМК<br/>ABAC: мед. допуск +<br/>лечащий врач пациента)
    EMR[(ЭМК: Postgres + S3 для сканов<br/>теги c3/medical,<br/>шифрование at rest, ключи в Vault)]
    AUD[(Журнал аудита<br/>SIEM)]

    PAT -- "анамнез — только данные,<br/>необходимые для лечения" --> VISIT
    VISIT -- "заключения, назначения<br/>TLS" --> EMR
    EMR -- "история болезни — только<br/>лечащему врачу (ABAC)" --> VISIT
    VISIT -. "каждое чтение/запись c3" .-> AUD
```

Меры: общий диск исключён; доступ к медкарте — только у медперсонала с атрибутом «лечащий врач»; расширенная анкета не собирается без цели обработки; retention-тег управляет сроком хранения.

## P3. Оплата услуг

```mermaid
flowchart LR
    PAT[Пациент]
    CASH(P3. Приём платежа<br/>RBAC: роль cashier)
    KKM[ККМ]
    PAY[(Платёжный сервис<br/>теги c2/payment,<br/>шифрование at rest)]
    BUH[(1С:Бухгалтерия<br/>клиент-серверный режим)]
    ACC(P3.1. Процессинг платежей<br/>RBAC: роль accountant)

    PAT -- "оплата<br/>TLS" --> CASH
    CASH -- "фискальная операция" --> KKM
    KKM -- "данные чека<br/>защищённый API вместо OLE,<br/>mTLS" --> PAY
    PAY -- "проводки, контракт интеграции<br/>с контролем состава полей" --> BUH
    BUH -- "платёжные документы<br/>маскированные реквизиты" --> ACC
```

Меры: двойной учёт в Excel упразднён — единственный источник истины; канал ККМ переведён с OLE на защищённый API; 1С — в клиент-серверный режим.

## P4. Учёт анализов

```mermaid
flowchart LR
    PAT[Пациент]
    LAB[Лаборатория анализов]
    TAKE(P4. Забор биоматериала<br/>и оформление направления)
    GW(API-шлюз интеграции<br/>контракт скрывает лишние<br/>категории данных)
    EMR[(ЭМК / результаты<br/>теги c3, шифрование)]
    DOC[Мед. специалист<br/>ABAC: лечащий врач]

    PAT -- "Ф. И. О., дата рождения<br/>или QR-код направления из ЛК<br/>при заборе биоматериала" --> TAKE
    TAKE -- "направление: surrogate ID,<br/>пол и возраст — без Ф. И. О.<br/>и контактов, mTLS" --> GW
    GW -- "заказ исследования" --> LAB
    LAB -- "результаты, mTLS,<br/>привязка по surrogate ID" --> GW
    GW -- "результаты автоматически,<br/>без ручного сканирования" --> EMR
    EMR -- "доступ по ABAC" --> DOC
```

Меры: псевдонимизация в обмене с лабораторией — контрагент не получает полный набор ПДн; API-контракт исключает доступ к чужим данным (проверка принадлежности по subject ID); ручное сканирование упразднено.

## P5. Бухгалтерия, кадры, зарплата

```mermaid
flowchart LR
    EMP[Сотрудник]
    HR(P5. Кадровый учёт<br/>RBAC: роль hr/accountant)
    BUH[(1С:Бухгалтерия<br/>клиент-серверный режим,<br/>теги c2/hr, шифрование БД)]
    FNS[ФНС, СФР]
    BANK[Банк]
    AUD[(Журнал аудита)]

    EMP -- "ПДн — по защищённой форме" --> HR
    HR -- "кадровые записи" --> BUH
    BUH -- "отчётность<br/>по защищённым каналам операторов ЭДО" --> FNS
    BUH -- "зарплатные реестры<br/>шифрование банк-клиента" --> BANK
    HR -. "операции с ПДн" .-> AUD
```

Меры: файловый режим 1С заменён на клиент-серверный с разграничением доступа на уровне СУБД; доступ к зарплатным данным — только у роли «бухгалтерия».

## P6. Учёт ТМЦ и закупки

```mermaid
flowchart LR
    SUP[Поставщик]
    WH(P6. Учёт ТМЦ<br/>RBAC: роль warehouse)
    TIS[(1С:Торговля и склад<br/>клиент-серверный режим, теги c1)]
    BUH[(1С:Бухгалтерия)]

    SUP -- "накладные, счета" --> WH
    WH -- "приход/расход" --> TIS
    TIS -- "проводки — контракт интеграции,<br/>только необходимые поля" --> BUH
```

Меры: обмен между базами 1С — по контракту с контролем состава полей; данные ТМЦ (c1) не смешиваются с ПДн.

## P7. Отчётность и аналитика

```mermaid
flowchart LR
    SRC[(Операционные БД<br/>теги c2/c3)]
    CLS(Движок классификации<br/>и псевдонимизации<br/>тегирование перед загрузкой)
    DL[(Озеро данных ClickHouse<br/>только обезличенный слой)]
    BA(P7. BI-отчёты<br/>контролируемая среда,<br/>RBAC: роль analyst)
    MGMT[Руководство]
    CAT[(Каталог данных<br/>теги + lineage)]

    SRC -- "ETL, TLS" --> CLS
    CLS -- "surrogate ID вместо ПДн,<br/>агрегаты вместо c3" --> DL
    CLS -. "регистрация датасетов и тегов" .-> CAT
    DL -- "обезличенные данные" --> BA
    BA -- "P&L, ABC-анализ<br/>без ПДн" --> MGMT
```

Меры: аналитика только на псевдонимизированных данных; локальные выгрузки и Jupyter на рабочей станции упразднены — работа в контролируемой среде; каталог данных обеспечивает lineage от источника до отчёта.
